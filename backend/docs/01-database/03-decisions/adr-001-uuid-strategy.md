# ADR-001: UUID v7 كـ Primary Key الوحيد لكل الجداول

| | |
|---|---|
| **الحالة** | ✅ مُعتمد (Frozen) |
| **الجلسة** | Session 3 — Database Standards |
| **يؤثر على** | كل الجداول السبعة بدون استثناء |

---

## السياق (Context)

كل جدول في قاعدة بيانات SentinelX يحتاج Primary Key. الخيارات المطروحة كانت:

1. `Auto Increment Integer` (التقليدي)
2. `UUID v4` (عشوائي بالكامل)
3. `UUID v7` (مرتب زمنيًا)

---

## القرار (Decision)

**كل Primary Key في النظام هو `UUID v7`.** لا يوجد Auto Increment Integer في أي جدول.

```text
id UUID v7 PRIMARY KEY
```

---

## الأسباب (Rationale)

### لماذا UUID وليس Auto Increment؟
المنصة **Public-Facing** (SDK، REST API عامة). لو استخدمنا Integer متسلسل، سيكون من السهل تخمين IDs:

```text
/company/1
/company/2
/company/3
```

أي طرف خارجي يمكنه استنتاج حجم المنصة أو الوصول لسجلات بالتسلسل. الـ UUID يحل هذه المشكلة الأمنية تمامًا.

### لماذا UUID v7 تحديدًا وليس v4؟

| الخاصية | UUID v4 | UUID v7 |
|---------|---------|---------|
| ترتيب زمني | ❌ عشوائي بالكامل | ✅ مرتب حسب وقت الإنشاء |
| أداء الـ Indexing | ❌ يسبب Fragmentation عالي في B-Tree Indexes | ✅ يقلل الـ Fragmentation بشكل كبير |
| ملاءمة PostgreSQL | متوسطة | ✅ ممتازة |
| مناسب لـ Distributed Systems مستقبلًا | ✅ | ✅ (وأفضل بسبب الترتيب الزمني) |

الـ UUID v4 العشوائي بالكامل يجعل كل إدخال جديد (Insert) يضرب مكانًا عشوائيًا داخل شجرة الـ Index، مما يزيد تكلفة الصيانة والقراءة مع نمو الجدول. UUID v7 يحل هذه المشكلة لأنه يحتفظ بترتيب زمني تقريبي، فتُدرج القيم الجديدة بالقرب من نهاية الشجرة دائمًا — تمامًا مثل سلوك Auto Increment، مع الحفاظ على عدم قابلية التخمين.

---

## البدائل المرفوضة

| البديل | سبب الرفض |
|--------|-----------|
| Auto Increment Integer | يسمح بتخمين الـ IDs — غير مقبول لمنصة عامة (Public Platform) |
| UUID v4 | ترتيب عشوائي بالكامل → أداء أسوأ في الـ Indexes مع نمو البيانات |

---

## العواقب (Consequences)

- ✅ حماية طبيعية ضد تخمين الـ IDs (Enumeration Attacks).
- ✅ أداء Indexing أفضل بشكل ملحوظ مقارنة بـ UUID v4.
- ✅ جاهزية للتوسع نحو Microservices أو Distributed Systems مستقبلًا دون الحاجة لتغيير استراتيجية المفاتيح.
- ⚠️ حجم تخزين أكبر قليلاً مقارنة بـ Integer (16 بايت مقابل 4-8 بايت) — قرار مقبول مقابل الفوائد الأمنية والمعمارية.
