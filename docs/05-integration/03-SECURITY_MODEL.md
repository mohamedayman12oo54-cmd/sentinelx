# Security Model

## Overview

The Security Model defines how SentinelX authenticates clients and protects communication between platform components.

---

# Authentication Model

Version 1 uses Agent API Keys as the primary authentication mechanism for Observation submission.

Each API Key uniquely identifies:

- Organization
- Agent

---

# Authorization

Authenticated Agents may only submit Observations associated with their own identity.

Authorization rules are enforced by the Backend.

---

# Observation Identity

Observation payloads do not contain organization identifiers or agent identifiers.

Identity is resolved exclusively from the authenticated API Key.

---

# Transport Security

All communication must occur over HTTPS.

Unencrypted communication is not supported.

---

# API Key Management

API Keys are:

- Generated by SentinelX
- Securely stored
- Rotatable
- Revocable

---

# Security Principles

Version 1 follows:

- Least Privilege
- Separation of Responsibilities
- Immutable Observations
- Explicit Authentication
- Secure-by-Default
